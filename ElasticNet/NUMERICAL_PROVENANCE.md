# Elastic Net numerical provenance

## Workflow version 1.0.0 — 2026-10-06

- Algorithm: binary SAGA updates from scikit-learn 1.9.1's compiled `sag32`
  kernel, with `C=0.1`, `l1_ratio=0.5`, Elastic Net regularization, and
  train-only median imputation, scaling, missing indicators, and one-hot text
  encoding. The fit objective is penalized logistic log loss. Validation
  misclassification at a fixed 0.5 cutoff is monitored after every epoch.
  Version 2 gives 202403, 202404, and 202405 total validation weight shares
  60%, 30%, and 10%; these weights do not affect fitting.
- State and randomness: every epoch calls the compiled kernel once, retaining
  coefficients, intercept, gradient memory, gradient sums, seen-sample flags,
  and seen count. The kernel flushes lazy coefficient updates at every epoch
  boundary. Epoch `e` draws stochastic samples from a seed generated by
  `SeedSequence([random_state, e + 1])`. Full optimizer snapshots and the
  accumulated validation history are checksummed and atomically published.
  This sampling schedule is reproducible but differs from the single RNG
  stream in one monolithic public scikit-learn fit. No estimator `warm_start`
  is used.
- Runtime versions: Python 3.12, NumPy 2.5.1, SciPy 1.18.1, scikit-learn
  1.9.1, pandas 3.0.3, Hydra 1.3.4, Matplotlib 3.11.1, threadpoolctl 3.7.0,
  and tqdm 4.69.0. BLAS and OpenMP threads were set to one in timed runs.
- Reference comparison: using 400 randomly selected training rows from each
  of the ten v1 training months and 1,000 randomly selected 202404 rows,
  training-only preprocessing produced 651 features. After 500 epochs with
  `tol=0` on both implementations, this workflow's probabilities versus public
  `LogisticRegression(solver="saga", penalty="elasticnet", l1_ratio=0.5,
  C=0.1)` had mean absolute difference `8.62e-5`, 99th-percentile absolute
  difference `4.93e-4`, and maximum absolute difference `0.00125` on the
  validation rows. Both had misclassification rate `0.175` at 0.5. Different
  stochastic sample streams account for nonzero coefficient and probability
  differences. The 500-epoch fits took 8.342 seconds and 8.399 seconds,
  respectively, with one BLAS/OpenMP thread.
- Checkpoint regression: on the full source, v2's 180-epoch checkpoint was
  resumed to epoch 200. Its final coefficients, intercept, entire 200-row
  history, gradient memory, gradient sums, seen flags, and seen count matched
  the uninterrupted 200-epoch run bitwise. The checkpoint source, schema,
  hyperparameters, and exact numerical package versions were verified before
  resuming. A smaller synthetic regression test also checks this equality.
- Actual-data benchmark: the full two-protocol 200-epoch run took 2:38.83
  wall time, 284.54 seconds of user CPU time (180% aggregate CPU), and
  2,467,032 KiB peak resident memory. The training matrix had 652 features
  per protocol, including 81 numeric missing indicators. Version 1 used
  133,676 training and 28,679 validation rows; version 2 used 120,583
  training and 41,772 validation rows. A separate three-epoch v1 run took
  11.76 seconds total and 2,046,324 KiB peak resident memory.
- Final validation on saved models: v1 on v1 had misclassification `0.198124`;
  v2 on its weighted native protocol had `0.185761`; v2 on the unweighted v1
  202404–202405 period had `0.197671`. These are scores on the supplied
  undersampled validation rows, not an independent test set. Both 200-epoch
  fits reached the configured epoch cap before the `1e-4` coefficient-change
  tolerance; final relative coefficient changes were `0.000461` for v1 and
  `0.000594` for v2. The last fitted models were retained as configured.
- Validation-weight implementation check: on all 41,772 actual v2 validation
  rows, a vectorized month lookup reproduced the earlier per-row mapping
  bitwise. The one-call timings were 0.000962 and 0.004735 seconds,
  respectively. This is a small preprocessing improvement with no change to
  the weighted validation score.
